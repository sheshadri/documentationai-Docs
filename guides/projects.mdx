A project groups the testing work for an app: its target URL, scans, saved access methods, test suites, runs, and integrations. Open a project from the dashboard to work with it.

## Find your results

| Area | What you can do |
| --- | --- |
| Overview | Inspect the selected scan's pages or screens and their findings. |
| Issues | Investigate reported problems. |
| WCAG reports | Review and export accessibility reports. |
| Tests | Review suites and start test runs. |
| Runs | Inspect executions, failures, and evidence. |
| Coverage | Review available coverage information and checks. |
| More | Find additional views such as analytics, recommendations, baselines, and web and app testing. |

Use the scan selector to inspect the intended scan. Results from an older scan do not automatically describe your latest deployment.

## Configure the project

Open **App access** to manage sign-ins. Open **Project setup** for test data, environments, variables and secrets, schedules, CI/CD, integrations, notifications, members, and project settings.

In **Project settings**, review the project name and website URL before changing the target used by future work.

## Work with teammates

In **Project setup → Members**, add existing teammates or invite a new teammate by email. Choose the appropriate project role: **Admin**, **Member**, or **Viewer**. Member management requires the appropriate owner or administrator access.

Project membership and subscription ownership serve different purposes. Ask the organization owner to handle billing changes.
