## Recent Updates

SecuredAll releases updates regularly to enhance human-like testing for web and mobile apps. You can find detailed release notes for each version below, including new features like WCAG reports and Playwright exports, improvements to scanning speed, and critical bug fixes.

<Callout kind="success">
  The latest version `v1.2.0` introduces WCAG evidence reports and faster mobile testing. Update now for the best experience.
</Callout>

<Update label="2024-12-05" description="v1.2.0" tags={["feature", "improvement"]}>

## New Features

- Added WCAG 2.2 A/AA evidence reports with authenticated page coverage, reproducible sampling, and manual review notes.
- Support for printable PDF exports of scan results, including detected failures and exclusions.

## Improvements

- Reduced scan times by `30%` for login-aware workflows using real browsers and devices.
- Enhanced independent test review with page-level evidence screenshots.

## Bug Fixes

- Fixed intermittent failures in mobile APK/IPA testing on iOS simulators.
- Resolved export issues when tests included dynamic content.

</Update>

## Upgrading SecuredAll

Follow these steps to upgrade to the latest version and migrate your workflows.

<Steps>
  <Step title="Backup Your Data" icon="database">

    Export your previous scans:

````bash
securedall export --workspace your-workspace-id > backup.json
````

  </Step>
  <Step title="Update CLI" icon="download">

    Install the latest version:

    <CodeGroup tabs="npm,yarn">
```bash
npm install -g @securedall/cli@latest
```

```bash
yarn global add @securedall/cli@latest
```
    </CodeGroup>

  </Step>
  <Step title="Run Migration" icon="settings">

    Migrate configs for breaking changes:

````bash
securedall migrate --from v1.0.0 --to v1.2.0
````

    Review the output for any manual steps.

  </Step>
  <Step title="Test Scan" icon="zap">

    Verify with a simple scan:

````bash
securedall scan https://example.com --api-key YOUR_API_KEY
````

  </Step>
</Steps>

<Callout kind="alert">
  For `v1.0.0` to `v1.1.0` migrations, update your auth tokens to use `{API_KEY}` format.
</Callout>
